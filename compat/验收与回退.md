# 本地候选验收与回退

这些步骤供用户手动验收。候选尚未在实机运行；本地打包不会安装文件、启动游戏或附加进程。只在目标游戏 SHA256 为 `9585d3d993874d65156aba633c00b8a25faab3afde8953a8a183c80fb8f657ac` 且已有 sora1looseload v0.2.0 的环境中验收。

## 安装和启动

1. 退出游戏，备份已有的 `mods/VoiceRandomizer/` 与 `voice/wav/voice_randomizer/`（若存在）。保留根目录现有的 `xinput1_4.dll`。
2. **已安装上一份兼容候选且素材完整时**，使用 `dist/VoiceRandomizer-fork-candidate-module-update.zip`，只合并 `mods/VoiceRandomizer/` 下两个文件，保留现有配置、素材与编辑器。**首次安装或需要恢复素材时**，使用 `dist/VoiceRandomizer-fork-candidate-install.zip`，按原结构合并 `mods/` 和 `voice/`；完整包的默认配置会覆盖同名 INI，先备份自己的配置并在安装后恢复。不要把嵌套文件压平到根目录。两个包二选一，更新包不含音频数据。
3. 先以默认配置启动，确认 loader 识别模块、游戏进入标题画面且无初始化错误。检查日志 `voice/wav/voice_randomizer/VoiceRandomizer.log`。原设置程序继续从同目录读取 `voice_randomizer.ini`。

## 手动验收矩阵

| 验收项 | 操作 | 预期结果 |
| --- | --- | --- |
| `new` / `old` | 将 `[Randomizer] Mode` 依次设为 `new`、`old` 后重启；`old` 时选一个有有效 WAV 的语音 | `new` 始终使用游戏语音；`old` 使用旧语音，有效旧资源缺失时回到游戏语音 |
| 同一句 `alternate` | 设为 `alternate`，重复触发完全相同的语音名数次 | 每个具体语音名各自从新语音开始，再新旧交替；不同语音名互不推进同一交替位 |
| 基础随机 | 设为 `random`，关闭 `GuaranteeEnabled` 与 `CapturingRadianceEnabled`，把 `OldPercent` 设为 0、100 后分别播放多条可用语音 | 0 只选新语音，100 只选旧语音；中间数值按旧版基础概率随机选择 |
| 保底 | 设 `Mode=random`、`CapturingRadianceEnabled=0` 并等配置刷新。每个目标用例先设 `GuaranteeEnabled=0` 并等刷新，再设目标与概率，最后设 `GuaranteeEnabled=1` 并等刷新。分别测试 `GuaranteeTarget=new`、`OldPercent=100` 和 `GuaranteeTarget=old`、`OldPercent=0` | 每个用例先得到一次非目标普通结果，下一条符合条件的随机语音强制为目标版本；关闭捕获明光后可单独检查保底 |
| 捕获明光 | 关闭保底、开启捕获明光；以 `GuaranteeTarget=new`、`OldPercent=100` 连续播放有效语音 | 三次普通旧版未命中后，下一次仍抽取一次但强制为新版本并清零计数；改目标为旧版并设 `OldPercent=0` 时结果镜像 |
| 模式暂停状态 | 在 `random` 中累计状态，切换到 `new`、`old` 或 `alternate` 再切回 `random` | 强制模式不抽随机数也不推进保底/明光状态；切回随机后继续此前状态 |
| 配置热更新 | 保存概率、日志或 Overlay 项，观察运行中变化；再更改 `GuaranteeTarget`、保底或捕获明光开关 | 除 `ReplacementSet` 外的设置约 1 秒重读；目标/两机制开关变化时同时清空两类规则状态，概率、日志与 UI 更改不重置规则状态 |
| `ReplacementSet` | 修改 `[Randomizer] ReplacementSet` | 本候选安装包只附带 `legacy` 数据。实现也支持 `placeholder`，但该数据集需另备在 `voice/wav/voice_randomizer/assets/placeholder/`；更改后重启游戏 |
| 历史 Overlay | 播放超过 10 条语音，隐藏再显示 Overlay；改变左边距、垂直中心、区域高度、滚动时长 | 最多显示最近 10 条，最新从底部进入；隐藏时记录仍保留，位置和动画按设置刷新 |
| 原游戏与其他 loose Mod | 检查原字幕/对白标注、相机功能及其他 loose-file Mod；确认 loader 根目录 `xinput1_4.dll` 哈希未变 | 原加载器继续工作，字幕、相机和其他 loose Mod 正常；语音候选不替换其文件 |

随机模式下，普通非目标结果会推进保底与明光计数；保底和捕获明光互相独立，保底先处理。UI 开关独立于语音总开关。`LogCache=1` 可临时打开缓存命中/未命中日志，完成诊断后可恢复默认值。

## 当前差异与回退

整目录迁移后，游戏缓存 helper 会丢弃目录和扩展名，只保留小写 basename。模块对自身启动时已验证的资源别名进行缓存键处理：把规范化的 `voice/wav/voice_randomizer/assets/old/<原名>` 映射到缓存键 `vr_old_<原名>`；为已验证的 placeholder 项保留 `vr_test_<原名>` 命名空间。未知名称、其他目录或非模块路径仍交给游戏原 helper。此处只改变缓存身份；WAV 文件名和字节不变，资源打开继续经过现有 loose-file loader。

当前实现启动时验证旧资源，并在每次播放前检查文件；如果播放前文件缺失或同步排队失败，会回到游戏语音，已提交的抽取状态不撤销。原模块还拥有异步文件 open hook：语音已排队后、实际异步打开前旧 WAV 被删除时，它可以在打开阶段改用新版。目录迁移候选不保留这个 open hook，所以在该时间窗口内不再执行打开阶段回退。不要把启动/播放前检查描述成覆盖了此异步窗口。

若需回退，先退出游戏，再删除本次新增的 `mods/VoiceRandomizer/` 与 `voice/wav/voice_randomizer/` 两个目录。若安装前目标目录已存在，使用安装前备份恢复。保留根目录的 `xinput1_4.dll`、其他 Mod 和游戏文件；不要删除整个 `mods/` 或 `voice/` 目录。
